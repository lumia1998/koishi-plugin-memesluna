# 项目改进与验证

## 已实现

1. 图片存储：同存储目录的写操作串行化；重复上传复用已有记录；移动检查数据库和磁盘重名并使用排他复制；写入、移动、删除和归档提供失败补偿。启动时规范化文件名也保留冲突文件及已有标注。读取权限错误不再作为文件丢失清除记录。
2. 管理权限：HTTP `/api/admin/*` 与所有 MemesLuna Console RPC 统一校验 Koishi auth 登录凭据、过期/撤销状态和当前用户权限。上传在校验成功后解析；缺少 auth 服务时拒绝管理访问。公开发图、搜索和端点转发保持可访问。
3. 搜索：单字与混合查询在大库下保留全扫描结果；图片与倒排索引共同缓存；合并并发刷新；读取期间发生写操作会重读，避免发布已失效数据。
4. 相似分组：使用 BK-tree 精确检索汉明距离近邻，取消超过 200 张时的前缀分桶。成员与代表图必须达到阈值，展示最低代表相似度。
5. 前端：分页获取图片和标注；旧请求结果失效；批量任务限制并发并保留失败项；追加标注由服务端合并；连续编辑串行保存。暂缓区预览通过带鉴权的请求加载，卸载时释放资源。
6. AI：统一标注队列、请求并发限制、超时、取消及进度状态；tagall 整批入队，取消后不重新提交后续分块。每次请求提前持久化配额，包含失败及重试，并分别统计成功和失败结果。Console 预览页提供状态和取消入口。
7. 维护性与性能：独立存储协调、相似索引、标注调度/队列、前端分页及批量模块；合集汇总统一读取数据库；ChatLuna 路由清单随变更刷新。

## 权限修复验证

结论：`fixed`。原来无需登录就能通过管理 HTTP 或 Console RPC 到达上传、删除等操作；修复要求所有这类调用先通过身份及当前权限检查。公开发图是必须保留的合法行为。

采用两个传输入口共享的凭据校验器，未更改数据库服务的公开发图逻辑。HTTP 使用 Console Bearer 凭据，RPC 保留 Console Client 的调用上下文并声明 authority。显式校验避免仅声明 authority 而在 auth 插件未启用时放行。

涉及文件：`src/admin-auth.ts`、`src/http-server.ts`、`src/console-handlers.ts`、`src/index.ts`、`client/composables/adminFetch.ts`、`client/components/shared/AuthenticatedImage.vue` 及相应前端调用者。`tests/admin-auth.test.ts` 覆盖匿名、错误凭据、缺少 auth、过期、撤销、权限不足和无效到期时间。

原问题在 HTTP 实际请求及 RPC 回调边界不再复现：未授权请求返回 401 或 Unauthorized，业务服务和上传解析不会执行。合法凭据可以管理、上传并查看暂缓区预览；匿名请求仍能读取公开图片。权限部分完成一次独立只读复核，未发现遗留绕过或兼容性问题。

## 使用与验证范围

管理端需启用 Koishi auth，并使用权限至少为 1 的 Console 账号。自定义管理客户端需发送 Bearer 凭据。图片上限和 AI 配额语义变化详见 README。

文件操作使用进程内协调和失败补偿，不等同于跨进程或断电场景的文件/数据库分布式事务。AI 配额使用磁盘账本；取消和超时会发送 AbortSignal，底层请求实际结束前继续占用槽位，防止忽略取消的提供方造成并发超限。

测试中的数据库、用户凭据和模型均为隔离测试数据。验证未调用真实付费模型、连接真实机器人或完成浏览器端人工验收，也不包含实际机器人部署。
